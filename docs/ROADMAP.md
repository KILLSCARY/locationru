# Roadmap

Дорожная карта развития платформы Resilient Taxi. Документ отражает текущее
состояние кода на ветке разработки и порядок дальнейших работ. Приоритеты
выстроены так, чтобы сначала закрыть «временные ограничения этапа», явно
отмеченные в архитектурной документации, а затем расширять клиентов.

## Условные обозначения

- ✅ — реализовано и покрыто тестами
- 🟡 — реализована архитектура/интерфейс, внешняя интеграция ещё dev-заглушка
- ⬜ — запланировано, не начато

## Текущее состояние

### Backend (`apps/api`, NestJS + Prisma + PostGIS + Redis)

| Домен                               | Статус | Комментарий                                                         |
| ----------------------------------- | :----: | ------------------------------------------------------------------- |
| Auth (OTP, JWT, refresh)            |   🟡   | Логика готова; SMS через `DevelopmentSmsProvider` (код в лог)       |
| Trips + машина состояний            |   ✅   | Централизованный `trip-state-machine`                               |
| Dispatch (подбор водителей)         |   🟡   | PostGIS-поиск готов; ETA по прямой, без routing API                 |
| Driver locations (live + история)   |   ✅   | Валидация скорости, устаревания, rate limit                         |
| Bids (ставки водителей)             |   ✅   | TTL-ставки                                                          |
| Finance (комиссии, payout)          |   ✅   | Снапшот тарифа в транзакции создания поездки                        |
| Payments                            |   🟡   | Интерфейс + вебхуки + идемпотентность; `DevelopmentPaymentProvider` |
| Realtime (WebSocket + outbox)       |   ✅   | Транзакционный outbox, поллинг                                      |
| Admin (аудит)                       |   ✅   | REST под `/api/v1/admin`                                            |
| Health (`/health`, `/health/ready`) |   ✅   | Проверка PostgreSQL и Redis                                         |

## Этап 1. Закрыть внешние интеграции ядра

Цель — заменить `Development*`-провайдеры на реальные и снять пометки
«временное ограничение этапа». Интерфейсы уже спроектированы, работа
локализована за абстракциями.

### 1.1 Платёжный провайдер 🟡

Каркас готов: выбор провайдера по окружению и боевая заготовка на месте.
Осталось подключить конкретный шлюз.

- [x] Провайдер выбирается фабрикой (`payment-provider.factory.ts`):
      `development` вне production, `http` — в production.
- [x] Секреты провайдера через env + Joi-валидация (`PAYMENTS_*`); в
      production `PAYMENTS_PROVIDER=http` обязателен.
- [x] Боевая заготовка `HttpPaymentProvider` с HTTP-клиентом (base URL,
      авторизация, таймаут) и реальной проверкой HMAC-подписи вебхуков;
      денежные методы кидают `NotImplemented`, чтобы прод не имитировал
      платежи.
- [x] Идентификатор провайдера (`provider.name`) пишется в intent/payout/
      webhook вместо хардкода `'development'`.
- [ ] Реализовать методы `HttpPaymentProvider` под конкретный шлюз (ЮKassa /
      T-Bank / CloudPayments) через хелпер `request()`.
- [ ] Полный цикл: авторизация → списание → возврат; маппинг статусов на
      домен поездки.
- [ ] E2E-тесты сценариев успех/отказ/возврат/повторный вебхук на реальном
      (sandbox) шлюзе.

### 1.2 SMS-провайдер 🟡 → ✅

- [ ] Реализовать боевой `SmsProvider` вместо `DevelopmentSmsProvider`.
- [ ] Ретраи и обработка ошибок доставки, метрики отправки.
- [ ] Не логировать OTP вне `NODE_ENV=development`.

### 1.3 Диспетчеризация: реальный routing 🟡 → ✅

- [ ] Ввести интерфейс маршрутизации и адаптер внешнего routing API.
- [ ] Заменить оценку подачи по прямой (сейчас
      `DISPATCH_AVERAGE_SPEED_METERS_PER_SECOND`) на ETA с учётом дорог и
      пробок.
- [ ] Кэширование/деградация: при недоступности routing API — фолбэк на
      текущую геодезическую модель.

Довести Kotlin-приложение от модульной заготовки до рабочего клиента.

- [ ] Auth-флоу (OTP), хранение токенов, refresh.
- [ ] Экран заказов и приём/ставка на заказ (feature/orders, feature/auth).

- [ ] Подключение realtime-событий через `core/network`.
- [ ] Экраны home / earnings.
- [ ] Прогон detekt и unit-тестов домена.
