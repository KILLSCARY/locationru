# Dispatch: поиск кандидатов

`DispatchService.findCandidates()` — внутренний use-case, который возвращает
кандидатов для последующей отправки предложения. Он не назначает водителя и не
изменяет `selectedDriverId` заказа.

Поиск выполняется в PostGIS по последней неустаревшей записи `driver_locations`
для каждого водителя. В выборку попадают только водители со статусом `ONLINE` и
верификацией `APPROVED`; `BUSY`, `SUSPENDED`, `OFFLINE`, старые и помеченные
устаревшими позиции исключаются.

Радиус начинается с `DISPATCH_INITIAL_RADIUS_METERS` и умножается на
`DISPATCH_RADIUS_MULTIPLIER` до `DISPATCH_MAX_RADIUS_METERS`. Первое кольцо с
кандидатами формирует результат. Кандидаты ранжируются по предполагаемому
времени подачи, затем по расстоянию, затем по рейтингу и стабильному `driverId`.

Каждый запуск записывается в `dispatch_attempts`, а каждый возвращённый кандидат
— в `dispatch_attempt_logs`. Повторный вызов для того же заказа не возвращает
уже журналированного водителя. Повтор допускается только при явной
`redispatchReason`, которая также сохраняется в попытке.

## Оценка времени подачи

Геопоиск кандидатов (фильтр по радиусу и предварительная оценка ETA по прямой)
остаётся в SQL как дешёвый предфильтр: расстояние считается через PostGIS, а
секунды подачи — делением на `DISPATCH_AVERAGE_SPEED_METERS_PER_SECOND`. Поверх
шортлиста ETA уточняет `RouteEstimator`, выбираемый фабрикой по
`DISPATCH_ROUTING_PROVIDER`:

- `straight-line` (по умолчанию) — `StraightLineRouteEstimator` возвращает
  геодезическую оценку без изменений. Модель не учитывает дорожную сеть,
  пробки, односторонние улицы и правила маршрутизации. Допустима в production.
- `http` — `HttpRouteEstimator` обращается к внешнему routing API (base URL,
  ключ и таймаут из `DISPATCH_ROUTING_*`) и при недоступности API деградирует
  на оценку по прямой. Метод `fetchDurations` пока не подключён к конкретному
  API — до подключения провайдер ведёт себя как `straight-line`.

После уточнения ETA кандидаты пересортировываются (`rankDispatchCandidates`),
поэтому реальная маршрутизация может изменить порядок относительно оценки по
прямой.

## Проверка PostGIS-интеграции

После применения миграций к отдельной тестовой БД можно выполнить реальный
географический тест:

```bash
RUN_POSTGIS_INTEGRATION=true pnpm --filter @resilient-taxi/api test:e2e
```

Он проверяет расширение радиуса и исключение `BUSY` и устаревших водителей.
