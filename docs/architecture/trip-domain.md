# Домен поездки

`Trip` — агрегат поездки. Координаты pickup, destination и промежуточных остановок
сохраняются в PostGIS как `geography(Point, 4326)`, поэтому расстояния считаются
по поверхности Земли. Для пространственного поиска на этих колонках созданы
GiST-индексы.

## Деньги

Все денежные значения хранятся в копейках (`*Kopecks`) как целые числа. Комиссия
хранится в basis points: 100 означает 1%, 10000 — 100%. Миграция запрещает
отрицательные деньги, расстояние, длительность и версию агрегата.

## Состояния

Статусом нельзя управлять напрямую через API или Prisma-вызов прикладного кода.
Изменение выполняется только `TripStateMachine`, который централизованно хранит
таблицу допустимых переходов.

Каждый успешный переход выполняется транзакционно:

1. Считывается текущий статус и `version`.
2. Проверяется, что переход разрешён.
3. Строка обновляется с условием на текущий `version` и получает `version + 1`.
4. В той же транзакции создаётся `TripStatusHistory`.

Если другая операция уже изменила поездку, сервис возвращает
`TRIP_VERSION_CONFLICT`; история в таком случае не создаётся. Попытка перейти в
недопустимый статус возвращает `INVALID_TRIP_TRANSITION`.

Первоначальные REST endpoint’ы для поездок намеренно не добавлены: доменный
сервис подготовлен для будущих application/use-case модулей.

## Пассажирский заказ

Пассажир создаёт заказ через `POST /api/v1/trips`. Заказ всегда появляется в
`DRAFT`; его можно перевести в `SEARCHING` только через `start-search`. Создание
требует заголовок `Idempotency-Key`. Ключ сохраняется вместе с SHA-256 хешем
нормализованного тела запроса: повтор того же запроса возвращает исходный draft,
а другой payload с тем же ключом возвращает конфликт.

На уровне базы partial unique index не позволяет пассажиру иметь более одного
активного заказа. Активными считаются статусы от `DRAFT` до `IN_PROGRESS`; после
терминального или failed статуса можно создать новый заказ.

`cancel` идемпотентен: повторная отмена пассажиром возвращает существующий
`CANCELLED_BY_PASSENGER` без создания новой записи истории.
