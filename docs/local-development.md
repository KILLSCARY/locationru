# Локальная интеграционная среда

Локальный stack предназначен только для разработки и интеграционных проверок.
Он использует development SMS/payment providers, которые не отправляют SMS и не
переводят деньги. Карты и внешние routing API не подключаются.

## Требования

- Node.js 20 или новее;
- pnpm 10;
- Docker с Docker Compose;
- свободные порты 3000, 3001, 5432 и 6379.

Подготовьте локальное окружение из корня репозитория:

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
```

Значения из `.env.example` предназначены только для локальной разработки. Перед
запуском можно заменить пароли и test secrets; `.env` не добавляется в Git.

## Полный stack

```powershell
pnpm dev:stack
```

Команда последовательно:

1. запускает PostgreSQL 17/PostGIS 3.5 и Redis;
2. применяет Prisma migrations и создаёт тестовые аккаунты;
3. запускает NestJS API на `http://localhost:3000`;
4. запускает admin-web на `http://localhost:3001` (порт задаётся через
   `ADMIN_WEB_PORT`);
5. запускает генератор свежих координат тестового водителя.

`DevelopmentSmsProvider`, lifecycle test payment provider и
`DevelopmentPaymentProvider` работают внутри процесса API. Они намеренно не
оформлены как внешние сервисы: данные не покидают локальный компьютер. API не
запустит эти providers при `NODE_ENV=production`.

Остановите процессы приложений сочетанием `Ctrl+C`. PostgreSQL и Redis останутся
запущенными, чтобы данные сохранялись; остановить их можно командой
`pnpm infra:down`.

## Тестовые аккаунты

Все телефоны и development OTP задаются через `.env`:

| Роль          | Переменная                  | Значение по умолчанию |
| ------------- | --------------------------- | --------------------- |
| Пассажир      | `SEED_PASSENGER_PHONE`      | `+79990000001`        |
| Водитель      | `SEED_DRIVER_PHONE`         | `+79990000002`        |
| Администратор | `SEED_ADMIN_PHONE`          | `+79990000000`        |
| OTP           | `AUTH_DEVELOPMENT_OTP_CODE` | `111111`              |

Водитель создаётся со статусом проверки `APPROVED` и одним автомобилем
`APPROVED`. Повторный `pnpm dev:seed` обновляет те же записи и не создаёт
дубликаты.

## Seed и reset

Запустить инфраструктуру, применить migrations и повторно создать fixtures:

```powershell
pnpm dev:seed
```

Полностью удалить локальные PostgreSQL/Redis volumes, создать чистые volumes,
применить migrations и seed:

```powershell
pnpm dev:reset
```

`dev:reset` безвозвратно удаляет только данные именованного development Compose
проекта `resilient-taxi`. Не запускайте команду, если локальные данные нужно
сохранить.

## Автоматический journey

```powershell
pnpm test:journey
```

Команда сама поднимает PostgreSQL/PostGIS и Redis, применяет migrations, запускает
seed и проводит одну поездку через реальные API controllers и сервисы:

1. пассажир, водитель и администратор проходят development OTP-аутентификацию;
2. водитель становится ONLINE и отправляет координату;
3. пассажир создаёт поездку за 130000 копеек и запускает поиск;
4. PostGIS dispatch находит тестового водителя;
5. водитель предлагает 145000 копеек;
6. пассажир выбирает предложение, комиссия фиксируется как 8%;
7. mock payment резервируется, водитель выезжает и прибывает;
8. проверяется четырёхзначный код посадки;
9. поездка завершается и переходит в `SETTLED`.

Тест дополнительно проверяет комиссию 11600 копеек, выплату водителю 133400
копеек, историю статусов и локальную запись расчёта. Мобильный UI не требуется.

## Генератор координат

Генератор авторизуется как тестовый водитель и отправляет небольшое движение
вокруг координаты `DEV_DRIVER_LATITUDE`/`DEV_DRIVER_LONGITUDE`. Частота задаётся
`DEV_DRIVER_LOCATION_INTERVAL_MS`. Это синтетические GPS-точки для разработки;
они не являются картой, навигацией или точными данными сотовых вышек.

## Ограничения

- SMS-код только пишется development provider в структурированный лог API;
- платежи существуют только в памяти mock provider и локальных таблицах;
- генератор координат не использует GNSS, карты или routing API;
- environment не предназначен для staging или production.
