# Карта пассажирского приложения

Все экраны используют `MapComponent = getMapView()` (см.
`mobile-map-architecture.md`) и общий слой `src/maps/*` — ниже описано, как
он собирается в конкретные пользовательские сценарии.

## Главный экран заказа (`app/trip/new.tsx`)

- Полноэкранная карта, кнопка «Моё местоположение» (центрирует камеру через
  `MapCameraController.focusPoint`), поля «Откуда»/«Куда» с поиском адреса
  (`@/features/maps/api` — `suggest`, geocode), выбранные точки
  отображаются маркерами (`pickupMarker`/`destinationMarker`) и линией
  маршрута (`routePolyline`), нижняя панель — расстояние/время/
  рекомендованная цена/цена пассажира/кнопка «Найти водителя».
- Маркеры и линии карты собираются через `useMemo`, завязанный на
  координаты точек и геометрию маршрута, а не на весь стейт экрана — ввод
  текста в поля адреса не вызывает полной перерисовки карты.

### Режим «указать на карте» (`pickMode`)

- Пользователь двигает карту с зафиксированным центральным маркером-пином;
  `onCameraIdle` вызывает `handleCameraIdle`, который:
  - **дебаунсит** обратное геокодирование (300 мс) и **отменяет**
    предыдущий незавершённый запрос через `AbortController`, если камера
    продолжает двигаться;
  - показывает индикатор загрузки, пока запрос не завершится;
  - при ошибке показывает понятное сообщение и не блокирует продолжение;
  - позволяет подтвердить точку, даже если адрес ещё не резолвился (тогда
    сохраняются только координаты) — «Подтвердить» не заблокирована
    состоянием загрузки геокодинга.
- Подтверждение сохраняет **точный снимок**: координаты центра камеры на
  момент подтверждения + последний резолвленный адрес (или его отсутствие)
  — а не адрес, к которому «в конце концов» пришло геокодирование.

## Экран поиска водителя (статус `DRAFT`/`SEARCHING`/`OFFERS_RECEIVED`)

`SearchingSection` в `app/trip/[id].tsx`: маршрут, точка подачи, точка
назначения, зона поиска (окружность/область вокруг точки подачи), и
**только агрегированная** информация о кандидатах — количество
подходящих машин и примерная ETA подачи, без точных позиций свободных
водителей (сервер их и не отдаёт на этом статусе — см.
`docs/api/driver-locations.md`). Анимированный индикатор поиска, пока
активных откликов (`bids`) нет.

## Экран выбранного водителя (`DriverEnRouteSection`)

После выбора отклика (`bid.accepted`) экран показывает: машину, её живую
позицию (сглаженную — см. `location-rendering.md`), маршрут до пассажира,
точку подачи, ETA, точность геолокации и статус качества
(`LocationQualityStatus`). Маркер водителя обновляется через
`DriverMarkerInterpolator` — не телепортируется на каждое WS-событие, а
плавно едет между засечками (кадрами) GPS.

## Активная поездка (`ActiveTripSection`, статус `IN_PROGRESS`)

- Живая позиция машины, маршрут, разбиение на «пройдено»/«осталось»
  (`computeRouteProgress` из `routeProgress.ts`, проекция текущей позиции
  на ближайший сегмент маршрута), ETA, статус поездки.
- Кнопка SOS — сейчас `Alert.alert`-заглушка (нет требования интеграции с
  реальной экстренной службой в рамках этой задачи).
- Кнопка «Поделиться поездкой» — использует `ShareTripService`
  (`src/features/share/shareTrip.ts`). Бэкенд не имеет эндпоинта выдачи
  токена для публичной ссылки на поездку, поэтому подключён только
  корректный интерфейс (`ShareTripService`) и development-реализация
  (`DevelopmentShareTripService`, возвращает
  `https://share.resilienttaxi.dev/t/{token}` и `isDevelopmentOnly: true`)
  — без реальной отправки ссылки куда-либо.
- Кнопка сворачивания нижней панели — не закрывает карту, только уменьшает
  занимаемую высоту шторки.

## Камера

`MapCameraController` (см. `mobile-map-architecture.md`) отвечает за:

- подгонку области обзора под весь маршрут при построении маршрута
  (`fitRouteBounds`);
- фокус на точке подачи/назначения/машине по запросу (`focusPoint`);
- автослежение за машиной (`startFollowingDriver` /
  `updateDriverPosition`) — отключается при ручном перетаскивании карты
  (`onManualCameraMove`) и возвращается кнопкой «Вернуться к машине»
  (`resumeFollowing`);
- защиту от резких скачков камеры: `updateDriverPosition` пересчитывает
  камеру только если машина сдвинулась больше `minMoveMetersToRecenter`
  (8 м по умолчанию) или изменила курс больше
  `minBearingChangeDegrees` (12°) — иначе камера остаётся неподвижной.

## Обновление в реальном времени

`src/api/realtime.ts` — один socket.io-сокет на сессию
(`subscribeToTripRoom`), по комнате `trip:{tripId}`; отслеживает номер
последовательности каждого события (`RoomSequenceTracker`), игнорирует
старые/дублирующиеся события, при обнаружении разрыва запрашивает
довосстановление через существующий WS-механизм `events.replay`
(бэкенд не имеет отдельного REST-эндпоинта для ресинка — задание
называет это «REST resync», реализовано через уже существующий WS-канал,
см. `location-rendering.md`). Переподключение — с экспоненциальным
backoff и повторной аутентификацией текущим токеном; при размонтировании
экрана подписка снимается (`unsubscribe`).
