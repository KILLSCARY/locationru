# Архитектура провайдеров геоданных

API работает только с внутренними интерфейсами `GeocodingProvider`,
`RoutingProvider`, `MapMatchingProvider` и `PlacesProvider`. DTO и доменные
сервисы не импортируют SDK или типы конкретного поставщика. Выбор выполняется
через `MAPS_PROVIDER`.

## Провайдеры

- `development` — полностью офлайн, детерминированные адреса Санкт-Петербурга
  и Мурино, прямые отрезки вместо дорожной сети. Запуск в production запрещён.
- `yandex` — HTTP-адаптер Yandex Geocoder API и Yandex Router API. Ключ
  передаётся только через `MAPS_API_KEY`; он не попадает в ответы, логи и Git.

Если в development выбран `yandex`, но ключ отсутствует, API явно переходит на
офлайн-провайдер. В production отсутствие ключа или выбор development-провайдера
останавливает приложение. Для перехода на другого поставщика нужно реализовать
те же четыре интерфейса и изменить фабрику в `MapsService`; публичные контракты
и клиенты при этом не меняются.

HTTP-адаптер использует таймаут, ограниченные экспоненциальные повторы для 429 и
5xx, нормализованные ошибки и circuit breaker. Актуальные форматы запросов:
[Yandex Geocoder API](https://yandex.com/maps-api/docs/geocoder-api/request.html)
и [Yandex Router API](https://yandex.com/maps-api/docs/router-api/request.html).
Перед staging следует проверить тариф и квоты в кабинете Яндекс: сам проект не
подключает платный план автоматически.

## Ключи и стоимость

Секрет хранится в переменной окружения/секрет-хранилище среды развертывания.
`MAPS_API_URL` и `MAPS_ROUTING_API_URL` позволяют переключить официальные
endpoint без изменения кода. Redis-кэш, debounce клиента и лимит API уменьшают
число оплачиваемых запросов. Метрики квот и расходов остаются обязанностью среды
эксплуатации — провайдер не возвращает их в публичный API.
