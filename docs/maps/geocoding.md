# Геокодинг и поиск адресов

Доступны авторизованные endpoints:

- `GET /api/v1/maps/address-suggestions?query=...&latitude=...&longitude=...&limit=5`;
- `POST /api/v1/maps/geocode`;
- `POST /api/v1/maps/reverse-geocode`.

Запрос подсказок содержит не менее 3 символов, `limit` ограничен значением 10,
широта и долгота проверяются по мировым границам. Ответы нормализованы в
`AddressSuggestion` и `ResolvedAddress` из `packages/contracts`; исходный ответ
провайдера наружу не передаётся.

Ключ кэша строится из нормализованной строки, округлённой географической
привязки, лимита и имени провайдера, затем хэшируется SHA-256. Так адрес не виден
в имени Redis-ключа. TTL отдельно задаются для подсказок, прямого и обратного
геокодинга. In-flight дедупликация и короткая Redis-блокировка защищают от
одновременного заполнения одного ключа.

Офлайн-набор содержит: Екатерининскую улицу, 30 в Мурино; Невский проспект, 45;
Московский вокзал и аэропорт Пулково. Это тестовые координаты, не каталог адресов.
