# Геокодинг и поиск адресов

## Эндпоинты

- `GET /api/v1/maps/address-suggestions?query=&latitude=&longitude=&limit=` —
  подсказки адресов по тексту. `query` — минимум 3 значимых символа
  (`isSearchableQuery`), `limit` — 1..10 (по умолчанию 5). `latitude`/
  `longitude` — необязательный bias (координаты пользователя), обе или ни
  одной.
- `POST /api/v1/maps/geocode` `{ address }` — резолвит текстовый адрес в
  координаты. `404 ADDRESS_NOT_FOUND`, если адрес не распознан.
- `POST /api/v1/maps/reverse-geocode` `{ latitude, longitude }` — резолвит
  координаты в ближайший адрес. `404 LOCATION_NOT_FOUND`, если рядом ничего
  нет.

Все три эндпоинта требуют Bearer-токена (`AccessTokenGuard`), их не отдаёт
внутренняя реализация провайдера клиенту — ответ содержит только
`ResolvedAddress`/`AddressSuggestion` (см. `packages/contracts`), без деталей
конкретного API.

## Нормализация запросов

`normalizeAddressQuery` (`apps/api/src/maps/geo/address-normalizer.ts`)
приводит текст к единому виду перед сравнением/кэшированием:

- нижний регистр;
- `ё` → `е` (совпадение «Королёва»/«Королева»);
- запятые/точки/точки-с-запятой убираются;
- пробелы схлопываются в один.

Это гарантирует, что «Невский, 45» и «невский 45» бьют в один и тот же кэш и
дают одинаковый набор результатов у `DevelopmentMapsProvider`.

## Кэширование

`MapsCacheService` — read-through кэш поверх Redis
(`apps/api/src/maps/cache/maps-cache.service.ts`). Ключи формирует
`apps/api/src/maps/geo/cache-keys.ts`:

- `maps:v1:<provider>:suggest:<limit>:<bias>:<hash>` — TTL
  `MAPS_SUGGESTIONS_TTL_SECONDS` (по умолчанию 300 с).
- `maps:v1:<provider>:geocode:<hash>` /
  `maps:v1:<provider>:reverse:<lat,lng>` — TTL `MAPS_GEOCODING_TTL_SECONDS`
  (по умолчанию 86400 с — адреса меняются редко).

Правила:

- ключ всегда включает имя провайдера — переключение провайдера никогда не
  возвращает чужой кэш;
- координаты округляются до ~1.1 м (`roundCoordinate`), поэтому
  почти-идентичные точки используют один ключ;
- `null`/пустой результат никогда не кэшируется (`isCacheable` в
  `MapsService`) — недоступность адреса не залипает в кэше;
- защита от cache stampede: при промахе первый вызов берёт короткую
  Redis-блокировку (`SET NX EX`, 5 с), остальные параллельные вызовы ждут
  публикации результата (до ~600 мс) вместо параллельного похода в провайдер;
  если держатель блокировки не успел — следующий вызов просто считает сам.

## DevelopmentMapsProvider

Полностью офлайн-провайдер (`apps/api/src/maps/providers/development-maps.provider.ts`)
для разработки и тестов. Поддерживает 4 фиксированных адреса:

| Адрес                                 | Координаты (lat, lng) |
| ------------------------------------- | --------------------- |
| Мурино, Екатерининская улица, 30      | 60.0459, 30.4432      |
| Санкт-Петербург, Невский проспект, 45 | 59.9326, 30.3506      |
| Санкт-Петербург, Московский вокзал    | 59.9295, 30.3621      |
| Санкт-Петербург, аэропорт Пулково     | 59.8003, 30.2625      |

Поиск — совпадение нормализованных токенов запроса с токенами, выведенными из
`fullAddress`/`subtitle` самого адреса (не отдельный ручной список ключевых
слов), поэтому запрос, совпадающий с документированным адресом дословно,
всегда находится. Reverse geocoding снэпает к ближайшему из четырёх адресов.
Этот провайдер не делает сетевых запросов и не может быть выбран в
production (см. `provider-architecture.md`).
