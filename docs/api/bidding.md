# Торги пассажира и водителей

Водитель получает доступные ему заказы через
`GET /api/v1/driver/trips/available`. В список попадают только заказы, для
которых его ранее вернул Dispatch. Это предотвращает произвольные ставки на
недоступные заказы.

Для создания предложения водитель вызывает `POST /api/v1/trips/:tripId/bids`
и передаёт `vehicleId`. Поле `offeredPriceKopecks` необязательно: если его нет,
ставка принимает цену пассажира. Указанная цена должна быть целым числом не
меньше `TRIPS_MIN_PASSENGER_PRICE_KOPECKS`. ETA и расстояние до подачи
вычисляются сервером по свежей геопозиции водителя.

Одна пара «водитель + поездка» может иметь только одну активную ставку. Срок
действия задаётся `BIDS_TTL_SECONDS`; истёкшие ставки переводятся в `EXPIRED`
при операциях со ставками. Водитель может отозвать активную ставку через
`DELETE /api/v1/trips/:tripId/bids/:bidId`.

Пассажир читает активные предложения через
`GET /api/v1/trips/:tripId/bids` и выбирает одно через
`POST /api/v1/trips/:tripId/bids/:bidId/select`. Выбор выполняется в одной
транзакции: выбранная ставка становится `ACCEPTED`, остальные активные —
`REJECTED`, поездка переходит в `DRIVER_SELECTED`, а итоговая цена, комиссия и
выплата водителю фиксируются в поездке. Ни одна из этих операций не выполняет
автоматическое назначение без выбора пассажира.
